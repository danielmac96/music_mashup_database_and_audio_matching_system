# Mashup Engine — allin1, the downbeat + labelled-section engine (readme §5.5).
#
# Installed on top of requirements.txt, never instead of it, and in this order
# (the Dockerfile does it): allin1's and madmom's own metadata list bare or
# newer numpy / scipy / librosa / demucs, which a resolver would happily
# "upgrade" past this repo's pins — or refuse to resolve against them at all —
# so both go in with --no-deps and their real runtime needs are listed here.
#
#   pip install -r requirements-allin1.txt
#   pip install "madmom @ git+https://github.com/CPJKU/madmom@27f032e8947204902c675e5e341a3faf5dc86dae" --no-deps
#   pip install allin1==1.1.0 --no-deps
#   pip install natten==0.17.3 --no-build-isolation      # compiles, ~1-2 min
#
# Verified 2026-10-23 in the Docker image (Python 3.11, torch 2.5.1,
# numpy 1.26.4, scipy 1.12.0); the natten findings date from 2026-10-22 on
# Python 3.12.
#   * allin1 1.1.0 calls natten.functional.natten1dqkrpb / natten1dav, which
#     natten removed after 0.17.x. 0.17.5 imports torch.cuda's device query at
#     import time and fails on any machine without an NVIDIA driver; 0.17.3
#     does not. No CPU wheel was reachable (shi-labs.com), so it is built from
#     the PyPI sdist against the installed torch — hence --no-build-isolation
#     (and build-essential + cmake, already in the image).
#   * madmom's last PyPI release (0.16.1) does not import on Python >= 3.10;
#     the git main branch does. It is pinned to the commit above rather than
#     to @main, because a branch ref is not a pin: main last moved on
#     2024-08-25, and whatever it points at next would be installed silently.
#   * That madmom commit declares scipy>=1.13, which is unsatisfiable against
#     this repo's scipy==1.12.0 — left to the resolver the whole install dies
#     with ResolutionImpossible before natten is ever reached. The floor is a
#     NumPy 2 compatibility bump, not an API madmom uses: on scipy 1.12.0 /
#     numpy 1.26.4 it compiles, imports and tracks downbeats
#     (DBNDownBeatTrackingProcessor, checked 2026-10-23). So madmom goes in
#     dep-less too, with mido — its one other runtime dep — listed below.
#     Do NOT raise scipy to satisfy that floor instead: madmom/audio/hpss.py
#     imports scipy.ndimage.filters, which scipy removed in 1.15.
#   * The model weights (8 × ~20 MB, 'harmonix-all') download from HuggingFace
#     (taejunkim/allinone) on first use into the HuggingFace cache.
mido>=1.2.6                # madmom's one other runtime dep; listed here
                           # because madmom itself goes in --no-deps
hydra-core>=1.3
omegaconf>=2.3
huggingface_hub>=0.20
matplotlib>=3.7
numpy==1.26.4
scipy==1.12.0
cmake>=3.20
ninja
